# AI 赋能测试 · 知识框架速查

> 摘自 `AI赋能测试/知识框架/` **81 条**。课程笔记在 `笔记资料/`，会议总结在 `会议总结/`；更新框架时双目录扫描。仅拷 `AI测试/` 到新电脑时读此文件作补充。

## 全局原则

- **责任在人**：AI 是加速器，质量结论由人签字
- **无材料不编造**：缺 PRD/接口文档 → 标「待确认」，不臆造字段、状态码
- **先脱敏再粘贴**：见 Skill「前置：粘贴材料前」
- **幻觉应对**：所有结论须指向材料某句；模型自信不等于正确

## 00 工具与工作流

| 要点 | 做法 |
|------|------|
| 仓库认读 | 先自己指认 tests/、conftest、数据目录、文档目录，再让 AI 干活 |
| 只读模式 | 先 `@` 文件只读解释 → 看懂 → 再改 |
| 小步修改 | 一次改一类；限定文件和行号；改完跑用例 |
| Rules | 写清：语言、pytest 命令、目录约定、禁止项（不编造、不提交密钥） |

## 01 基础认知

| 能做 | 不能做 |
|------|--------|
| 草稿用例、提示词、数据分析 | 替代测试签字、保证无漏测 |
| 按材料生成结构化输出 | 编造未文档化的接口行为 |

## 02 提示词工程

- **紧提示** = 角色 + 任务 + 约束 + 输出格式
- **四段式**：见 Skill WF-1
- **评审四维**：完整性、可执行性、范围一致性、安全性

## 03 数据与校验

- 每字段：**正常值 / 边界值 / 异常值**
- 多字段组合：风险优先抽样，不全量笛卡尔积
- 校验失败：把字段路径+原因喂回 AI 重试，不贴整段堆栈

## 04 契约驱动测试

**四规范**：PRD（要什么）| 契约（接口长什么样）| Rules（边界）| Skill（怎么做）

**三种 gap**（双源对齐必查）：
1. PRD 有、契约无 → 待契约补全
2. 契约有、PRD 未验收 → 待产品确认
3. 语义不一致 → 标 gap，等澄清

**WF-2 用例表**（Markdown）：
- 先判**材料三态**：仅 PRD → 验收点清单（禁填 HTTP 码/字段）；仅契约 → 协议用例 + 待产品确认；双源 → 先矩阵再表
- 二道闸每项**必写出处**（`见 PRD §x` / `见 OpenAPI path → responses.NNN`）；写不出 = 不通过
- **缺条 ≠ 失败，编条 = 闸不过**：凑不够条数写 pending，不补编
- 闸过后 `## 待你确认`（gap / pending），用户表态前不进 WF-3 / WF-6

**Swagger → pytest 代码（WF-6）**：
- 阶段 A：**仅 skeleton + TODO**，禁止一次写满
- 五阶段：读物料 → 骨架 → **人工评审** → 补全 → 按业务流组织 → 执行
- 鉴权：token 从 login → Authorization；user_id 从 user info；**环境变量**，无明文入库
- 断言：**body 优先**；主路径通过后再补反向
- 与 WF-2 区分：表 vs 代码

**八维评分（可选）**：S1 格式 10 + S2 覆盖 15 + S3 正反向 15 + S4 数据 15 + S5 断言 15 + S6 脱敏 10 + S7 流程 10 + S8 可执行 10 = 100；≥85 良好。S2 仅双源齐全时评；已在 pending 标明缺口的不按缺失扣

## 05 排错与 fix loop

- **traceback 三要素**：异常类型、描述、文件行号
- **FixtureError at setup** → 改 fixture，不改用例
- **最小改动**：先方案 → 人审 → 只改报错行 → 复测
- **fix loop**：默认最多 **3 轮**；仍失败 → 停止、升级人工
- **禁止**：为通过测试直接改断言预期或硬编码
- **需求不明确** → 立即停止，标「待产品确认」，不猜测
- **修复依据**：定稿 PRD/契约 → 业务逻辑 → traceback → 测试代码
- **一页小结**：执行概览 / 根因 / 修改点 / 回归范围 / 残余风险 / 升级说明

## 00+ Harness / agents.md

- **Harness Engineering**：Rules + Skills + 契约 + 轮次限制 = 给 AI 套马具
- **agents.md**：项目根 AI 说明书（结构、可改/不可改、pytest 命令、fix loop 约定）

## 06 合规与安全

**红线（禁止上传公网 AI）**：生产库连接串、API Key、个人信息、内网拓扑、未公开商业数据、整份内网契约

**脱敏占位符**：`<TOKEN>` `<HOST>` `<USER>/<PWD>` `<PHONE>` `<ORDER_ID>` `<SESSION>`

**Token 管理**：上下文有限，关键约束放提示词末尾

**粘贴材料前四步检查**：① 看能否贴（查红线）→ ② 节选必要段 → ③ 手动脱敏 → ④ 再 @ 或粘贴

## 07 pytest 规范

- fixture 嵌套 **≤ 2 层**；默认 scope=function
- parametrize **ids 用中文**业务场景；禁 `test_data_0`
- **autouse 默认关**；开启须说明理由

**断言（WF-7）**：
- **先 body 后 status**（正例与反例同）
- **假绿**：只 assert status → 201 但 body 空仍绿；Check 前重新读文件
- 无 body 接口须说明原因
- **四结果**：红→绿 / 维持红 / **xfail**（超出契约状态码）/ **skip**（功能未实现）；reason 须有契约证据

## 08 测试可重复性（WF-8）

- **一次绿 ≠ 可重复**；连跑 2～3 次验证
- 残留：创建型 / 状态变更型 / 只读（只读不管）
- 清理优先级：幂等覆盖 → delete（best-effort）→ skip-on-exists + README
- **清理失败 ≠ 用例失败**；记 warning 不 raise
- finalizer：多清理用 `addfinalizer(cleanup)` 非 `cleanup()`
- README + agents.md：交代残留、恢复、特殊 flow（如不断言余额）

## 09 UI 自动化（WF-9）

- **`/ui-pom full`** 五阶段：读物料→PO→自检(B)→用例(C)→执行(D)→幂等(E)；Todo 分阶段
- smoke 数据（`自检`）与正式 yaml（`测试`）分离；B/D 未 PASS 不进下一阶段
- 截图 + agents.md → PO；定位自愈 ≤3 轮，仅定位类错误
- 失败缓存 `locator_failed_cache.yaml`；id>name>相对 XPath；禁 data-v-*
- 验证码：万能码 > cookie > OCR；不强解

## 10 知识库与 RAG

**基础（第14～16节）**：
- RAG：切片→Embedding→向量库→检索→（第17节）生成
- Chunking：逻辑单元 + metadata（source/section/doc_type）
- Embedding：**同 provider+model**；ingest/query/ask 共用 `embedding_fn.py`
- **四路径**：chroma_default | openai | sentence_transformers | ollama（见讲义 `embedding-providers.md`）
- **换模**：改 yaml → rebuild → ingest → query 验 `embedding: ...`
- **铁律**：同模型、换模重建、**脱敏先行**（未脱敏禁送外部 API）
- Chroma：`corpus/` 进 Git，`chroma_data/` **禁止**；collection 如 `test_spec_v1`
- query 输出：人看 **document + metadata**；distance 越小越匹配
- M3 栈：15 部署入库 → 16 切分 → 17 ask/LLM → 18～20 质量验收
- HITL：关键节点人审；第15节阶段先人工检索验证
- **建设原则**：知识库由**使用方**（如测试团队）主导——业务场景只有使用方最清楚

**语料工程（第16～17节）**：
- **语料来源**：测试规范、接口说明、changelog、复盘 runbook
- **入库三要素**：团队共享权限 + 已脱敏 + 版本管理
- **切分核心原则**：最小完整语义，每个 chunk 独立回答一个问题
- **切分过碎/过粗**：过碎→信息不完整，过粗→噪声大
- **按文件类型切分**：MD 按标题、OpenAPI 按 path+method、changelog 按条目、Excel 按 sheet/用例编号
- **递归切分**：先标题→超长再按段→再按句；像剥洋葱逐层细化
- **切分六看**：问题粒度、噪声比、上下文完整、文档类型、metadata、与 top-k 联动
- **A/B/C 演示**：整篇一块(1条噪声大)→按章节(4条基线)→精细切分(6条更稳)
- **metadata**：source（必填）、section、version、module、doc_type
- **多版本管理**：文件名带版本 + id 不冲突 + metadata.version + 检索 where
- **标准化入库工作流**：预检→格式转换→切分→metadata→入库→黄金问句验收→简报
- **三轮最小修复**：最多 3 轮；失败则上报；禁止大改动（换 Embedding/collection 结构）
- **3+1 验收**：3 条能答 + 1 条拒答（语料未覆盖的问题应输出拒答文案）

**检索与大模型（第17～18节）**：
- **四层调优**：数据层（切分+metadata）→ 存储层（Embedding/collection）→ 检索层（top-k/where）→ 路由层
- **where 条件**：通过 metadata 精确过滤，减少返回数量
- **top-k 调优**：通常 3～5；过大噪声大，过小可能漏
- **collection 路由**（选修）：为不同 collection 定义描述/关键词，让大模型自动选择；ask.py 当前未实现自动路由，需手动指定
- **禁止编造**：未找到时必须如实告知，不能编造或二次检索
- **提示词设计**：角色=测试规范问答助手；约束=仅依据检索片段、必须引用、片段不足则拒答
- **引用式作答**：格式 `【依据 <chunk_id>】<结论>`；每条结论必须标注来源
- **拒答文案**：`库中未找到相关条款。`（检索无结果时直接输出，不拼 prompt）
- **dry-run 模式**：`ask.py --dry-run` 只展示检索和 prompt，不调 LLM；无 Key 时课堂演示用
- **M3-18 质量 Harness**：五道门（检索门控→生成约束→引用 Schema→半自动 Check→HITL）；验收集 **3+1+1**；Bad Case A～G 分层回溯
- **流水线三层门禁**（会议总结 M3-19）与五道门不同：偏 ingest 入库校验
- 数据溯源：答案须可追溯到 chunk，无来源不可信
- **GraphRAG（第27节拓展）**：向量检索 + 关系层；不替代 Chroma 主线；关系问询才启用；拓展≠课内已交付

## 11 LLM 调用与 Agent 工具链（第19～28节）

**三种 Harness 勿混**：RAG 五道门 = **答案**质量；**调用侧** = API batch 工程；**任务侧** = Agent Task List + Art Check

**形态选型**：规范问库 → **ask**；批量造数/定时/CI 外围 → **API batch**；单条探索 → **IDE**；多任务无人值守 → **Agent Task List**

**API batch 流程**：读 tasks → checkpoint 断点续 → 循环调 API → results.jsonl；失败 → 退避 → dead-letter

**调用侧 harness 九项**：条数预算、timeout、429/5xx 退避（禁 busy-loop）、401 不重试、checkpoint 五字段、dead-letter（禁 silent pass）、节流、日志脱敏、Plan B 表

**checkpoint**：`job_id` / `input_path` / `last_done_index` / `updated_at` / `status`；已成功条目不重复调

**Agent 多任务**：Task List + Markdown 看板；状态 **pass / fail / unknown**（fail≠unknown）；调度 **关联 / 独立 / mixed**；跑批后 **Art Check 不可省**

**Schema Gate（第21节）**：三类失败 — ①调用 ②结构（Pydantic/exit≠0）③业务；fix-loop 摘要回灌；**校验通过≠业务正确**

**MCP（第22节）**：Host↔Server↔Tool；`mcp.json` **只挂载**；tools/list→tools/call；白名单=代码+边界文档；Skill **只指引调用**

**Agent（第23节）**：决策层选 Tool；MCP=执行插槽；默认 **HITL**；定制能力进 Agent Tool，复用能力进 MCP

**ReAct / Subagent（第24节）**：think→act→observe；Subagent 独立上下文、摘要回传、互不直连；**省主上下文 ≠ 总 Token 必少**；Loop=流程层，ReAct=运行时层

**三锁门禁（第25节）**：NL→映射表→suite_id enum；意图 / 脱敏 / 会话沙箱；执行层只认 enum；宁可拒识不越权

**平台设计（第26节·会议）**：配置层→执行层→代码层；结构先行；HITL/质检 Loop；正式讲义待补

**Agentic RAG / 开会型（第27节拓展）**：检索当 Tool + ReAct/预算/审计；开会型多 Agent 知悉即可；默认仍派工+互不直连

**工程形态拓展（第28节）**：自愈原理同构可落地；Playwright 与 Selenium 并行；AI 辅助 JMeter/Locust 非整替；进阶地图 A–F；会议总结待补
